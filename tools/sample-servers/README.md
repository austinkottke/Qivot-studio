# Sample servers

PostgreSQL, MySQL and SQL Server in Docker, each with Qivot Studio's four
sample databases loaded:

| Sample       | What it shows |
|--------------|---------------|
| `bookshop`   | Single and composite keys; CASCADE, SET NULL and plain references; a view |
| `university` | A circular reference (departments and their chairs); courses that need other courses (a many-to-many of a table to itself); a three-column composite reference (enrollments to sections) |
| `company`    | An org chart (employees managing employees); a text key (country codes); salary and job history keyed by date |
| `music`      | A record store: artists, albums and tracks; playlists (a many-to-many with an order); invoices; staff reporting to staff |

The same samples open in Studio as SQLite files from the welcome screen.

## Start

```bash
docker compose -f tools/sample-servers/docker-compose.yml up -d
```

The first start loads the data (SQL Server takes a minute or two, longer on
Apple Silicon, where Docker emulates it). SQL Server wants about 2 GB of
memory: if it keeps stopping (exit code 137), give Docker Desktop more under
Settings > Resources. Then in Studio, **Connect to
Server…**, pick the server, and click a sample name to fill in the rest:

| Server     | Address          | User    | Password         |
|------------|------------------|---------|------------------|
| PostgreSQL | `localhost:55432` | `qivot` | `qivot`          |
| MySQL      | `localhost:53306` | `root`  | `qivot`          |
| SQL Server | `localhost:51433` | `sa`    | `Qivot_Samples1` |

The databases are named after the samples. These are local test logins: don't
expose the ports beyond your machine.

To stop: `docker compose -f tools/sample-servers/docker-compose.yml down`
(add `-v` to delete the data too; the next `up` loads it again).

## How it's made

The samples are generated by Studio itself (`core/sampledatabase.cpp`),
described once and written for each database in its own types — so all four
databases hold exactly the same rows. `sql/` holds them as each server's own
script; after changing a sample, regenerate them:

```bash
tools/sample-servers/generate.sh
```

(`ctest` checks they're up to date.)
